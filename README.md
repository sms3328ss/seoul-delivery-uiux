# 서울배송

UI/UX 프로그래밍 수업용 가상 배송 안내 페이지입니다. HTML, CSS, JavaScript만 사용했습니다. 실제 업체나 운영 서버와 연결하지 않으며, 배송 접수·이메일 발송·결제는 하지 않습니다.

1~7주차 요구사항을 서울배송 주제로 다시 구성한 누적 보완본입니다. 주차별 커밋은 이번 보완 작업의 실제 작성 이력이며 과거 날짜의 제출을 재현한 것이 아닙니다.

## 주소와 실행
- 저장소: https://github.com/sms3328ss/seoul-delivery-uiux
- 배포 페이지: https://sms3328ss.github.io/seoul-delivery-uiux/
- 로컬에서는 같은 폴더의 index.html을 브라우저로 열면 됩니다. 별도 설치는 필요 없습니다.

## 사용자와 목표
- 사용자: 서울 안에서 서류나 작은 물건을 보내는 과정을 알아보려는 사람
- 서비스 목적: 필요한 배송 정보를 입력하고 확인하는 방법을 연습하기
- 핵심 행동: 배송 종류와 출발·도착 지역을 고르고, 예시 이메일을 입력한 뒤 내용을 확인하기
- 완료 조건: 필수 정보를 확인하고 '연습을 완료했습니다' 화면에 도달하기

2주차의 사용자·목적·핵심 행동·정보 순서는 HTML 주석에도 적었습니다. 주요 기능 3개, 이용 방법 3단계, 직접 그린 SVG 이미지와 대체 텍스트, 입력 영역과 내부 이동 메뉴를 넣었습니다. 서비스 소개의 세 가지 이용 방법을 실제 화면에서는 시작·입력·확인·완료의 네 화면으로 연결했습니다.

## 이벤트와 화면 변화
- click: 이메일 형식을 확인해 안내 색상과 버튼 상태를 바꿉니다. 서비스 안내 탭 3개는 선택 표시를 바꾸고 해당 내용만 보여 줍니다.
- input: 이메일을 수정하면 확인 완료 상태를 해제합니다. 요청 사항은 글자 수를 보여 주고 90자 이상이면 주의 색상으로 바꿉니다.
- change: 배송 종류를 고르면 서류·소형 물품에 맞는 준비 안내와 배경·테두리 색상이 바뀝니다.

## 7주차 사용자 흐름
1. 시작: 입력할 정보를 읽고 '연습 시작하기'를 누릅니다.
2. 입력·선택: 종류, 출발 지역, 도착 지역, 예시 이메일을 입력합니다. 요청 사항은 선택입니다.
3. 확인: 입력한 내용이 맞는지 확인합니다. 이전 단계에서 수정할 수 있습니다.
4. 완료: 완료 여부를 표시하고 처음부터 다시 시작할 수 있습니다.

## 인터랙션 시나리오
- 시작 버튼 → click → 시작 상태 → 입력 화면과 2단계 표시 → 입력·선택 상태
- 종류 변경 → change → 서류 또는 소형 물품 선택 → 안내 문구와 스타일 변경 → 입력 유지
- 이메일 확인 → click → 빈 값 또는 형식 오류 → 수정 방법과 오류 색상 표시, 입력칸으로 이동 → 입력 유지
- 이메일 확인 → click → 올바른 형식 → 성공 안내와 '확인 완료' 버튼 비활성화 → 확인된 입력 상태
- 이메일 수정 → input → 기존 값 변경 → 중립 안내와 확인 버튼 재활성화 → 다시 확인 가능
- 이메일 초기화 → click → 현재 이메일 여부와 관계없음 → 이메일·안내·확인 상태만 초기화 → 입력 유지
- 요청 사항 입력 → input → 글자 수 확인 → 숫자 갱신, 90자 이상 주의 표시 → 입력 유지
- 내용 확인 → submit → 필수 선택 누락 또는 이메일 오류 → 원인과 수정할 항목 안내 → 입력 유지
- 내용 확인 → submit → 필수 정보와 이메일 형식 정상 → 선택·입력값을 확인 화면에 표시 → 확인 상태
- 이전 단계 → click → 확인 상태 → 입력·선택값 유지 → 수정 후 재확인
- 연습 완료 → click → 확인 상태 → 완료 문구와 확인한 내용 표시 → 완료 상태
- 처음부터 다시 시작 → click → 완료 상태 → 입력·선택·안내·오류·확인 내용과 진행 상태 초기화 → 시작 상태

'시작 화면으로'는 이전 이동이므로 값을 유지합니다. '처음부터 다시 시작'은 흐름을 새로 시작하므로 값을 비웁니다.

## 테스트 결과
배포된 페이지에서 2026-10-20에 확인했습니다.

- 빈 이메일, @가 없는 값, 점이 없는 도메인을 입력하니 오류 문구와 오류 스타일이 표시됐습니다.
- student@example.com 입력 후 형식을 확인하니 성공 스타일과 버튼 비활성화가 표시됐습니다. 이메일 수정 시 다시 활성화됐고, 이메일 초기화 시 값과 안내가 초기 상태로 돌아왔습니다.
- 배송 종류·출발 지역·도착 지역을 각각 비워 다음으로 이동하니 해당 항목 안내가 나오고 입력 단계에 머물렀습니다.
- 서류와 소형 물품을 바꾸니 안내 문구와 스타일이 함께 바뀌었습니다. 요청 사항 90자를 입력하니 90 / 100자와 주의 스타일이 표시됐습니다.
- 세 탭이 각각 작동했고 선택된 내용만 표시됐습니다.
- 시작 화면으로 돌아온 뒤 다시 입력 화면에 가도 값이 유지됐습니다. 확인 화면에서 이전으로 돌아가 지역·이메일·요청 사항을 수정하니 새 값이 다시 반영됐습니다.
- 정상 흐름을 완료한 뒤 다시 시작하니 모든 입력값이 비워지고, 오류가 숨겨지고, 글자 수가 0으로 돌아가며 진행 단계가 1단계가 됐습니다. 확인·완료 내용도 비워졌습니다.
- 요청 사항을 비워도 완료할 수 있고 '요청 사항 없음'으로 표시됐습니다.
- 1100px·768px·390px 너비의 동일 페이지 iframe 미리보기에서 입력·오류·확인·이전·수정·완료·다시 시작을 조작했습니다. 시작·입력·확인 화면의 가로 스크롤과 화면 밖 입력창·버튼이 없었습니다. 1100px은 기능 카드 3열, 768px·390px은 1열과 세로 메뉴로 표시됐습니다. 실제 휴대폰 기기에서는 시험하지 않았습니다.
- 로그인 쿠키 없는 요청에서 저장소와 배포 페이지가 열렸고, CSS·JavaScript·SVG 파일이 현재 코드와 정확히 일치했습니다. 5·7주차 커밋의 고정 소스도 공개 접근을 확인했습니다. 커밋 상세는 브라우저에서 확인했으나 별도 외부 조회 도구에서는 503 응답이 있어 고정 소스로 추가 확인했습니다.
